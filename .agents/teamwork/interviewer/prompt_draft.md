Використовуй сабагентів для цього. Проаналізуй проєкт і його проблеми дотримуючись скілів та правил репозиторію.

Integrity mode: demo
The team must NOT:
- Use third-party libraries or frameworks outside of requirements.txt and Python standard library
- Modify or touch anything in harness/
- Commit or modify .env

## Requirements

### R1. Аналіз проєкту та його проблем
Використовуючи сабагентів, виконати аналіз поточної кодової бази проєкту ai-to-prod-workshop (зокрема `app/triage.py`, взаємодії з LLM, обробки помилок та граничних випадків). Сформувати короткий огляд стану та структурований чекліст виявлених дефектів і проблем. Файли у папці `harness/` та `.env` суворо заборонено змінювати; вносити зміни та експериментувати в `app/` та інших частинах проєкту дозволено. Результат надати безпосередньо у повідомленні без збереження окремого файлу звіту на диску.

### R2. Перевірка обмежень та вимог README.md
Перевірити відповідність поточної системи вимогам `README.md`:
- відсутність нових сторонніх бібліотек (дозволено лише `requirements.txt` та стандартну бібліотеку Python);
- збереження оригінального коду та контрактів у `harness/`;
- реалізація викликів LLM виключно через `openai` SDK без streaming із використанням `LLM_MODEL` та `GEMINI_API_KEY`;
- контракт вихідних даних: 5 обов'язкових ключів (`category`, `priority`, `needs_human`, `language`, `summary`), коректні типи, відсутність неперехоплених винятків та виконання у межах 20 секунд;
- стійкість до збоїв API (chaos, rate limits, timeouts) та prompt injection.

### R3. Дотримання агентських скілів та правил оркестрації
Під час аналізу керуватися правилами та скілами проєкту (`.agents/AGENTS.md`, `.agents/skills/`, `.agents/memory/`), зокрема дотримуючись протоколу економії токенів, ощадливого читання контексту та використання спеціалізованих сабагентів.

## Acceptance Criteria

### Deliverable & Format
- [ ] Надано короткий огляд поточного стану проєкту та структурований чекліст виявлених проблем із зазначенням рівня їх критичності.
- [ ] Результат представлено безпосередньо у повідомленні (без створення окремого файлу звіту на диску).
- [ ] Каталог `harness/` та файл `.env` залишилися недоторканими та незміненими.

### Rules & Quality Verification
- [ ] Чекліст покриває проблеми контракту (`harness/schema.py`), відповідності правилам класифікації, безпеки (prompt injection) та стійкості до збоїв API (chaos).
- [ ] Перевірено та відображено статус дотримання обмежень `README.md` (заборона сторонніх залежностей, конфігурація OpenAI SDK, недоторканність `harness/`).
- [ ] Аналіз проведено із залученням сабагентів відповідно до ролей та правил токен-економіки (`.agents/AGENTS.md`).
